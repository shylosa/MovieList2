# Розпізнавання й локалізація

`filename` ідентифікує локальний файл, а пара `media_type` + `tmdb_id` визначає твір. `TmdbID > 0` позначає розпізнаний запис, який усе ще може мати `NeedsReview`. AI дає назву, рік і тип як гіпотезу. ID для збереження надходить від TMDB. [storage.go](../../internal/storage/storage.go#L19), [app.go](../../recognition_coordinator.go#L536)

## Автоматичне сканування

1. `GetDiskFiles` повертає придатні файли з верхнього рівня джерел і один найбільший відеофайл із кожної підпапки першого рівня. Після повного обходу `RunScan` чистить відсутні записи, дозаповнює рейтинги й відбирає нові та unresolved файли. [scanner.go](../../internal/scanner/scanner.go#L26), [app.go](../../app.go#L691), [filterUnprocessed](../../app.go#L1602)
2. `runTMDBScan` виконує `ParseFilename` і коригує TV preference за груповим контекстом. Сильні маркери та сусідні слабкі номери з однаковою основою обробляються окремо. У змішаній папці рішення стосується лише відповідних файлів, а конфлікт із початковим `movie` може залишити `NeedsReview`. `FetchFromParsed` спочатку пробує IMDb `/find` у `uk-UA` (перший movie, інакше TV), далі запускає пошук за назвою для цього файла. [app.go](../../recognition_coordinator.go#L109), [parser.go](../../internal/tmdb/parser.go#L38), [client.go](../../internal/tmdb/client.go#L247), [app_group_test.go](../../app_group_test.go)
3. `buildAttempts` для кожного очищеного кандидата додає запит з роком, якщо відомий, і без року з тим самим `targetYear` для ранжування. Далі йде перша назва без року на протилежному endpoint, потім назва з батьківської папки з її розпізнаним роком і типом. Корінь відповідного джерела й generic-папки відсікаються. Кирилична назва папки може мати окрему латинську спробу. Після каскаду без прийнятого результату `pipelineCyrillic` пробує кирилиця→латиниця, а `pipelineLatin` використовує латиниця→кирилиця за фонетичними ознаками, обробляючи диграфи першими. [search.go](../../internal/tmdb/search.go#L418), [client.go](../../internal/tmdb/client.go), [translit_test.go](../../internal/tmdb/translit_test.go)
4. Автоматичний `searchAndFetch` шукає кирилицю в `uk-UA`, далі в `ru-RU`. Український збіг з балом від 140 завершує мовний каскад після перевірки деталей. Збій перевірки дозволяє далі шукати за чинним порядком. Латинський запит використовує `en-US`. Запит із відомим типом іде в його endpoint. Коли тип невідомий, порядок movie → TV у межах мови. Параметр року для TV — `first_air_date_year`, для movie — `year`. `normalizeForCompare` зберігає кириличні літери. `ё` бере участь у транслітерації та визначенні мови. [search.go](../../internal/tmdb/search.go#L589), [normalizeForCompare](../../internal/tmdb/search.go#L1221), [lang.go](../../internal/utils/lang.go)
5. `scoreResult` оцінює точний, частковий і fuzzy-збіг назви, рік і тип. Для перших трьох результатів зі слабким збігом можливі запити аліасів. `titleScore == 0` відхиляється. Фактичні пороги `rankResults` — 170 без року, 150 для точного року, 190 для сусіднього, 220 для конфлікту. Річний штраф `−400` у scoring діє від розбіжності у два роки. `verifySearchYear` застосовує постфільтр ±2 та допускає ранніший рік старту TV для TV-розбору. Search/details перевіряють однакові ID й тип, а близькі та конфліктні збіги можуть вимагати review. [models.go](../../internal/tmdb/models.go#L84), [search.go](../../internal/tmdb/search.go#L774), [client.go](../../internal/tmdb/client.go#L476)
6. Координатор `recognizeAutomaticScan` (R9-A) веде автоматичний скан одним ланцюжком: `runTMDBScan` → `processScanResults` → batch commit TMDB → `processGeminiQueue` для NO_MATCH → commit AI-пачок → черга локалізації. `processScanResults` після чистого промаху TMDB передає файл до `processGeminiQueue`: нова AI-гіпотеза перевіряється через TMDB тим самим механізмом (схожість оригіналу/аліаса від 0,85, сумісність року, тип), що й будь-яка інша гіпотеза. Історична таблиця `ai_resolutions` не читається й не пишеться (R6). Збої первинного пошуку TMDB журналюються й минають AI. Розпізнані результати й unresolved placeholders зберігаються через batch upsert із захистом підтвердженого запису; позитивні результати AI враховуються лише після commit каталогу. Останній етап локалізує підтверджені записи. [recognizeAutomaticScan](../../recognition_coordinator.go#L44), [processScanResults](../../recognition_coordinator.go#L302), [processGeminiQueue](../../recognition_coordinator.go#L368)

Автоматичний пошук використовує `(*MovieInfo, error)`.

| Результат | Значення | Дія автоматичного скану |
| --- | --- | --- |
| `(info, nil)` | TMDB підтвердив тип, ID і деталі за чинними критеріями. | Збереження в каталозі та локалізація за потреби. |
| `(nil, nil)` | Потрібні запити успішні, прийнятного збігу немає. | Нова AI-гіпотеза з подальшою TMDB-верифікацією. |
| `(nil, err)` | HTTP, transport, декодування або необхідна перевірка завершилися збоєм. | Діагностика й unresolved placeholder, якщо транзакція успішна. Файл придатний до повторного сканування. |
| `(nil, ctx.Err())` | Скасовано операцію. | Припинення каскаду, без нового placeholder чи наступного запиту. |

У межах одного каскаду зберігається перша істотна помилка. Пізній підтверджений збіг має пріоритет, а попередня невдала спроба лишається в діагностиці. HTTP 404 повертає `ErrNotFound` без повтору цього URL. Збій необов’язкового постера не змінює результат перевірки identity. [search.go](../../internal/tmdb/search.go#L418), [client.go](../../internal/tmdb/client.go#L194), [тести R4](../../internal/tmdb/search_outcome_test.go)

Кожний файл проходить власний каскад пошуку за назвою. `claimSearchAttempt` дедуплікує спроби лише в межах цього каскаду за нормалізованим запитом, роком у URL, цільовим роком, типом і набором мов. Кожна потрібна перевірка аліасів читає `/movie/{id}/alternative_titles` або `/tv/{id}/alternative_titles`. Повні деталі твору та деталі кандидата не кешуються й не об'єднуються через `singleflight` (R7, R8): кожне незалежне звернення — окремий запит до TMDB зі своїм context, тому скасування однієї операції не впливає на паралельні. `RunScan` і `FixSelected` скидають лише лічильники запитів. Шлях `LocalPosterPath` визначається для конкретного файла після завантаження деталей. [search_attempts.go](../../internal/tmdb/search_attempts.go), [client.go](../../internal/tmdb/client.go), [details.go](../../internal/tmdb/details.go), [app.go](../../app.go#L1247)

`loadMovieDetails` і `loadTVDetails` перевіряють кожну відповідь одразу після декодування. ID має бути позитивним і дорівнювати запитаному. Тип визначають за полями `title`/`original_title` або `name`/`original_name` і звіряють з `media_type`, якщо API його надав. Кожна HTTP-спроба декодується у чисту структуру. Невідповідність повертає помилку до об’єднання мовних відповідей, показу preview, завантаження постера й запису в SQLite. Це спільна перевірка для auto, exact, IMDb, ручного TMDB ID, preview, підтвердження кандидата й Refresh у Repair. Автоматичний каскад і далі обробляє помилки окремих спроб за поточними правилами fallback. [details.go](../../internal/tmdb/details.go), [search.go](../../internal/tmdb/search.go), [app_repair.go](../../app_repair.go)

## AI-гіпотеза та перевірка

| Етап | Фактичний контракт |
| --- | --- |
| Запит і кореляція | `internal/ai` зіставляє відповіді Gemini, Groq і Grok та повертає по одній позиції на вхідний файл у порядку запиту. `nil` позначає відсутній або конфліктний результат. App читає позицію файла. Перевагу має точний `request_id`. Legacy `id` приймається за відсутності ключа у відповіді та за однозначного зіставлення. Суперечливий `original_file` або конфліктний дубль відхиляється для відповідної позиції. Для справжнього пропуску діє до однієї послідовної спроби каскаду. Зіставлена відповідь із порожньою EN-назвою проходить чинну обробку порожньої назви. [gemini.go](../../internal/ai/gemini.go#L273), [app.go](../../recognition_coordinator.go#L368) |
| Валідність відповіді | Gemini і xAI парсять JSON у `RecognizedTitle`. Відсутній confidence там стає нулем. Groq окремо перевіряє явний `confidence` у `[0,1]` для кожного елемента та відхиляє весь результат за missing/null/out-of-range. Валідний JSON, навіть із порожніми назвами, завершує перебір моделей для цього виклику. [gemini.go](../../internal/ai/gemini.go#L351), [groq.go](../../internal/ai/groq.go#L106) |
| Корисність гіпотези | `mergeGeminiWithTMDBForType` вимагає `en_title`, порожній або `resolved` status і confidence ≥ 0,55. Спочатку `SearchExactTitle` на movie+TV (для strict — лише потрібний тип). Після чистого exact-промаху для non-strict можливий `FetchByCleanTitle` і додаткова TV-спроба, якщо movie не дав кандидата й операція активна. [app.go](../../recognition_coordinator.go#L536), [search.go](../../internal/tmdb/search.go#L207) |
| Результат AI→TMDB-верифікації (R9-B) | `mergeGeminiWithTMDB(ForType)` і `rescueEmptyGeminiWithFolder` повертають `(storage.Movie, error)`: `TmdbID > 0, err == nil` — FOUND; `TmdbID == 0, err == nil` — UNVERIFIED (непридатна/відхилена гіпотеза або чистий промах TMDB); `err != nil` — TMDB_ERROR (істотний збій API/мережі/JSON/перевірки, помилка не зводиться до промаху); `errors.Is(err, context.Canceled)` — CANCELED (`ctx.Err()`). Підтверджений збіг має пріоритет над помилками раніше дозволених спроб; у rescue перша істотна помилка зберігається локально до кінця дозволених спроб без кешу. Порядок і кількість HTTP-запитів не змінено. `processGeminiQueue` розрізняє результат: FOUND — у batch, accepted лише після commit; UNVERIFIED і TMDB_ERROR — чинний unresolved placeholder із захистом confirmed identity (TMDB_ERROR додатково логується); CANCELED — повернення без placeholder, HTTP-запиту чи наступної AI-пачки. Ручний `updateMovieWithMediaType` адаптовано без зміни поведінки: merge-помилка там лише діагностується, а не стає error-return. [recognition_coordinator.go](../../recognition_coordinator.go#L536), [тести R9-B](../../app_r9b_verify_outcome_test.go) |
| Фінальна перевірка | Сильна Jaro-Winkler схожість оригіналу або `MatchedAlias` ≥ 0,85, сумісність року з filename та AI (±1) і тип або сильна схожість ≥ 0,99. Локалізована схожість для AI merge є діагностикою. Точний локалізований збіг може потрапити до `MatchedAlias` із відповіді TMDB. [app.go](../../recognition_coordinator.go#L536), [geminiTMDBYearCompatible](../../recognition_coordinator.go#L925), [search.go](../../internal/tmdb/search.go#L186) |
| Невизначений результат | Якщо зіставлена AI-відповідь scan має порожню назву, `rescueEmptyGeminiWithFolder` пробує очищену папку, латиницю та обмежені варіанти `Sk→Sc`. Rescue приймає підтверджений ID/тип із JW ≥ 0,85, у т. ч. від TMDB localized/search title, без неоднозначного збігу. Після промаху, відсутнього елемента чи помилки batch формується `TmdbID=0`, `NeedsReview`, `review_reason=unresolved`, із захистом наявного підтвердженого запису. Запис залежить від успіху транзакції. [app.go](../../recognition_coordinator.go#L355), [rescueEmptyGeminiWithFolder](../../recognition_coordinator.go#L721) |

Каскад і лімітери описані в [STORAGE_LIFECYCLE.md](STORAGE_LIFECYCLE.md). Тести для ізольованих сценаріїв містяться в [gemini_test.go](../../internal/ai/gemini_test.go), [groq_test.go](../../internal/ai/groq_test.go), [search_test.go](../../internal/tmdb/search_test.go), [app_updatemovie_test.go](../../app_updatemovie_test.go) і [app_rescue_log_test.go](../../app_rescue_log_test.go).

## Мова й повторні спроби

Автоматичний пошук, точна назва й короткий список кандидатів використовують один HTTP-механізм `searchTyped` для `/search/movie` та `/search/tv`. Він кодує назву, додає мову й параметр року за потреби та використовує спільний HTTP retry. Порядок запитів і правила вибору визначає кожен режим. [searchTyped](../../internal/tmdb/search.go#L149)


Повні TMDB details звертаються до `uk-UA` → `ru-RU` → `en-US` з `credits`, завершуючи раніше за валідних українських назви й опису. Для вибору тексту fallback назви йде EN → RU, опису RU → EN. `IsGoodUkrainian` та `DetectTextLanguage` — евристики, зокрема для російських `ы`, `э`, `ъ`, `ё`. Локалізація працює по підтверджених ID, захищає валідні українські поля та може прийняти точний оригінал. Факт збереження логують після commit. [details.go](../../internal/tmdb/details.go#L54), [lang.go](../../internal/utils/lang.go), [app_localization.go](../../app_localization.go)

`localizeStoredMovies` може працювати навіть без нових файлів. `ForEachRecognizedLocalization` пропускає успішно оброблений незмінений snapshot. Автоматичний backfill також пропускає лише порожній опис при валідній українській назві. Зміна ID/типу/тексту, невалідна відповідь або помилка лишають запис придатним до повторної спроби за умовами черги. Явні дії редактора не використовують цей фільтр snapshot. [app.go](../../app.go#L1737), [storage.go](../../internal/storage/storage.go#L285), [app_localization_test.go](../../app_localization_test.go)

Для повідомленого кейсу «Охрана звёзд» → `Guarding Stars` див. [датований звіт](../reports/AGENT_CONTEXT_BASELINE.md#незавершена-верифікація). Підтримку конкретного запиту на сервері TMDB, роботу конкретних доступних моделей та якість на повній медіатеці перевіряють окремо. [DEVELOPMENT.md](../operations/DEVELOPMENT.md)

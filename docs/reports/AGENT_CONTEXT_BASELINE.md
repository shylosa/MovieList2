## Знахідки в коді за статичним читанням

- **P2. Підтвердження кандидата.** `ConfirmTMDBCandidate` перевіряє, що details повернув додатний ID, а потім зберігає отриману identity. Рівність повернутого ID із запитаним не перевіряється. Пізніше фонова задача використовує запитаний ID. Якщо details поверне інший додатний ID, foreground і background оперуватимуть різними identity. Для порівняння, `searchAndFetch` і `RefreshDetails` мають явний equality guard. Новий код чи політика цього сценарію поза цією ревізією. [ConfirmTMDBCandidate](../../app.go#L2082), [searchAndFetch](../../internal/tmdb/search.go#L691), [RefreshDetails](../../internal/tmdb/details.go#L301)
- **P2. GitHub Pages.** `deployToGitHubPagesIn` ігнорує будь-який результат commit, хоч `logGitFailure` розрізняє відсутність змін та інші помилки. Якщо commit помилковий, а push успішний, workflow може повідомити успіх без публікації нової вітрини. Існуючий тест продовження після commit failure використовує саме `nothing to commit`. Власник визначає бажану поведінку при інших commit errors. [app.go](../../app.go#L537), [app_git_log.go](../../app_git_log.go), [тест](../../app_lifecycle_github_test.go#L246)
- **P2. Лічильники scan.** `tmdb_accepted` формується до запису, а AI-черга може повернути розпізнані filenames після помилки batch save. Метрика прийняття може перевищувати кількість успішно збережених записів. Для доказу збереження звіряйте `batch_save_success` і `recognition_saved`. [RunScan](../../app.go#L727), [processGeminiQueue](../../app.go#L1265), [app_recognition_log.go](../../app_recognition_log.go)
- **P3. Шлях до лога.** `InitLogger` використовує директорію EXE, `OpenLogs` — поточну робочу директорію. За різних директорій кнопка може відкрити інший каталог. Це випливає зі шляхів, поведінку запущеного EXE тут не спостерігали. [logger.go](../../internal/utils/logger.go#L40), [OpenLogs](../../app.go#L316)
- **P3. Generated TypeScript.** `App.d.ts` типізує `GetModelSelections` через `main.ProviderModels`, але генерація в цьому checkout залишила `models.ts` без такого типу. Статична звірка позначила прогалину. JS wrapper існує й імпортується поточним UI, а TypeScript-компіляцію не запускали. [Go-тип](../../app_models.go#L17), [App.d.ts](../../frontend/wailsjs/go/main/App.d.ts#L25), [models.ts](../../frontend/wailsjs/go/models.ts)

## Незавершена верифікація

- **Повідомлення користувача від 21.11.2026.** «Охрана звёзд» автоматично не визначено, після ручного вводу `Guarding Stars` користувач підтвердив TMDB ID `1551025`. Код підтримує окремий ручний пошук і підтвердження. У простежених шляхах відсутня явна підстановка `ё→е`. Причина автоматичного промаху, записаний режим, файл журналу, точні відповіді TMDB і стан виконуваного EXE залишаються невідомими. Гіпотеза про роль `ё` потребує trace конкретного запуску й окремо погодженого відтворення. [Нормалізація](../../internal/tmdb/search.go#L1165), [ручні дії](../architecture/RECOGNITION.md#редактор)
- Результати старих синтетичних запитів не підтверджують сучасні квоти, каталог моделей, повну бібліотеку або Wails UI. Ручні сценарії лишаються у [DESIGN_CHECKLIST.md](../../DESIGN_CHECKLIST.md) і погодженому локальному checklist.

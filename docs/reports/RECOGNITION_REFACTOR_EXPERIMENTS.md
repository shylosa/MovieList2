# Експерименти з рефакторингу розпізнавання

## R1. Спільний типізований пошук TMDB

Варіант A починався з чистої гілки `main` на HEAD `18206aade80655a16456fd8f87426d8a9896e3ad`. Адресні фікстури запущено на A до зміни робочого коду, потім на B з тими самими вхідними даними й незалежними очікуваннями для запитів та результатів.

| Файли | Зміни |
| --- | --- |
| [search.go](../../internal/tmdb/search.go) | Три конструктори URL і три блоки виконання та декодування замінено на приватний `searchTyped`. Він приймає тип, назву, мову й `queryYear`, викликає чинний `doRequestWithRetry` і повертає результати або помилку. Порядок спроб, `targetYear`, ранжування та рішення про деталі залишаються в сценаріях. |
| [search_attempts.go](../../internal/tmdb/search_attempts.go), [details.go](../../internal/tmdb/details.go) | Разом із `search.go` використовують `utils.HasCyrillic`. Вилучений `hasCyrillicChars` мав той самий обхід рун і перевірку `unicode.Cyrillic`. У робочому Go-коді R1 прибрано 25 рядків за підсумком diff. |
| [typed_search_test.go](../../internal/tmdb/typed_search_test.go), [lang_test.go](../../internal/utils/lang_test.go) | Офлайн-фікстури HTTP та перевірки кирилиці, латиниці, змішаних назв, інших Unicode-писемностей, розширеної кирилиці, `ё`, `е` та порожнього рядка. |
| [RECOGNITION.md](../architecture/RECOGNITION.md), цей журнал | Актуальна схема спільного запиту й результати A/B. |

Маскована подія DEBUG `search_attempt` тепер формується в спільному механізмі, тому її отримують також exact і кандидати. Лічильники HTTP залишаються в чинному транспорті.

### Порівняння A/B

Фіктивний `RoundTripper` перехоплював усі виклики. У 39 записах збіглися метод, шлях, повний query string із маскованим ключем і порядок викликів. У 13 записах результатів збіглися повний JSON, порядок кандидатів і помилки. Окремі твердження тестів перевірили очікувані URL, identity, review, точний збіг і cancellation.

| Фікстура | Спостережений результат A і B | HTTP A → B |
| --- | --- | ---: |
| Auto movie, `Signal`, 2024 | `en-US`, спочатку `year=2024`, потім без року в URL. Вибрано `movie:42` за цільовим 2024, попри популярніший результат 2025 року. | 3 → 3 |
| Auto TV, `Ідея`, 2024 | Запит із `first_air_date_year=2024` у `uk-UA` вибрав `tv:42` і завершив мовний каскад. | 2 → 2 |
| Auto, невідомий тип, `Ёж + A&B?/#` | Movie → TV в `uk-UA`, далі той самий порядок в `ru-RU`, окремі параметри років. Назву повністю екрановано, результат порожній. | 4 → 4 |
| Exact, рік переважує preferred movie | Movie → TV в `en-US` без року в URL. TV-аліас підтвердив `tv:42`, review через конфлікт типу. | 4 → 4 |
| Exact, preferred TV за однакової оцінки назви | Movie → TV, аліас і деталі `tv:42`, review відсутнє. | 4 → 4 |
| Exact, strict movie | Один movie endpoint. Точний `movie:42` доступний з review через розбіжність року. | 2 → 2 |
| Exact, strict TV | Один TV endpoint. Точний аліас підтвердив `tv:42`. | 3 → 3 |
| Exact, fuzzy без підтвердження аліасом | Порожній результат, запит деталей відсутній. | 2 → 2 |
| Кандидати, `Zhertva obstoyatelstv` | Старт `en-US`, транслітерована назва в `uk-UA` → `ru-RU` → `en-US). У кожній спробі movie → TV. Порядок `tv:42`, `movie:42`, `movie:12`, `movie:13`, `tv:4`. Усі виклики пошукові. | 8 → 8 |
| Невалідний JSON, успішний повтор | Той самий URL повторено й декодовано `movie:42`. | 2 → 2 |

| HTTP 500, вичерпання повторів | Повернуто HTTP 500 після трьох спроб. | 3 → 3 |
| Скасування під час backoff | `context.Canceled` після першого HTTP 500, повтор відсутній. | 1 → 1 |
| **Усього** | **29 typed search, 6 details, 4 запити аліасів у кожному варіанті.** | **39 → 39** |

### Відомі дефекти та межі

- За кодом A і B видно, що auto може перетворити помилки всіх endpoint на пошуковий промах і закешувати його як `nil`. Раннє читання L1 у `FetchFromParsed` може завершити весь каскад за кешем базової спроби. [Вхід L1](../../internal/tmdb/client.go#L284), [запис промаху](../../internal/tmdb/search.go#L660)
- Кеш аліасів індексується числовим ID і може змішати докази для movie та TV. Exact також приймає деталі без звірки їхнього ID з обраним ID. Це відомі дефекти коду. Очікування офлайн-фікстур R1 не закріплюють цю поведінку як контракт. [Кеш аліасів](../../internal/tmdb/client.go#L952), [exact](../../internal/tmdb/search.go#L186), [аудит](AI_TMDB_FALLBACK_AUDIT.md)
- Фікстури перевіряють адресу, запити, локальне декодування, вибір і таймери на контрольованих відповідях. Якість на реальній медіатеці, живі відповіді TMDB, ситуація Guarding Stars з `ё/е` і решта матриці 28 сценаріїв залишаються неперевіреними в R1.

### Перевірки

Go 1.27.1 на Windows, тимчасовий `GOCACHE`, `GOTOOLCHAIN=local`, `GOPROXY=off`. Live-прапорці були відсутні.

| Команда | Результат |
| --- | --- |
| `go test ./internal/tmdb ./internal/utils -run '^(TestTypedSearchBaseline.*\|TestHasCyrillic)$' -count=1 -v` | Обидва пакети пройшли на A і B. Послідовності рядків `R1_WIRE` і `R1` з виводу збіглися повністю. |
| `go test ./internal/tmdb -count=1` | Пройшов. |
| `go test ./internal/ai ./internal/storage . -count=1` | Усі три пакети пройшли. |
| `go test ./... -count=1` | Усі 10 пакетів пройшли. |
| `go vet ./...` | Код виходу 0, діагностики відсутні. |
| `gofmt -w` і `gofmt -l` для п’яти змінених Go-файлів | Форматування застосовано. Повторна перевірка не вивела файлів. |
| `git diff --check` та локальна перевірка файлів | Код виходу 0. Перевірено UTF-8 без BOM, LF, пробіли в кінці рядків і 74 відносні посилання. |

**Рішення R1 — ACCEPT.** Спільний запит використовується в трьох сценаріях. Синтетичні фікстури показали однакові HTTP-запити, результати й помилки, включно зі скасуванням. На цих фікстурах не з’явилися хибні identity чи втрати очікуваних збігів.
